# Korean Law MCP 검토 및 GYO6 적용 방향

검토일: 2026-05-30

## 검토 대상

- 저장소: `https://github.com/chrisryugj/korean-law-mcp`
- 패키지: `korean-law-mcp`
- 라이선스: MIT
- 핵심 목적: 법제처 Open API를 MCP 도구로 감싸 LLM이 법령, 조문, 판례, 해석례, 인용 검증을 구조적으로 사용하게 하는 것

## 결론

GYO6 Law Info에는 즉시 외부 MCP 서버를 직접 붙이기보다, 공개 프로젝트의 좋은 구조를 참고해 우리 Worker 안에 "공식자료 우선 확인 -> AI 분석 -> 인용 검증" 흐름을 단계적으로 흡수하는 방식이 안전하다.

이유:

- 학생, 학교, 기업 관련 민감한 질문을 제3자 MCP 서버에 그대로 보내지 않는 것이 안전하다.
- npm 패키지를 실행하면서 API 키를 넘기는 방식은 키 유출 위험이 있으므로 운영 환경에서는 자체 검토 후 self-host 방식이 맞다.
- 현재 우리 Worker는 법제처 API에서 `HTTP 525`가 발생하므로, MCP 코드를 그대로 가져와도 Cloudflare Worker 내부에서는 같은 연결 문제가 반복될 수 있다.
- 다만 MCP의 재시도, 캐시, 인용 검증, 도구 선택 축소 설계는 우리 서비스 품질을 크게 올릴 수 있다.

## 참고할 핵심 아이디어

1. 법령 검색과 조문 조회를 분리한다.
2. 법령명 약칭, 오타, 부분매칭을 보정한다.
3. 검색 결과와 조문 조회 결과를 캐시한다.
4. LLM 답변의 법령명·조문 인용을 다시 검증한다.
5. 공식자료가 없거나 API 실패이면 "확인 필요"로 낮춘다.
6. 긴 체인 도구는 꼭 필요할 때만 쓰고, 단순 조회는 작은 도구로 처리한다.

## GYO6 적용 원칙

- 브라우저에서 MCP나 법제처 API를 직접 호출하지 않는다.
- 학생 이름, 학교명, 기업명, 연락처 등 민감정보를 MCP 검색어에 넣지 않는다.
- Worker가 먼저 공식자료 후보를 압축한 뒤 AI에게 전달한다.
- AI는 공식자료 후보에 없는 조문을 실존 조문처럼 단정하지 않는다.
- 최종 보고서에 "원문 확인됨", "직접 확인 필요", "API 실패"를 구분한다.

## 이번 반영 사항

Worker의 `/api/analyze`가 AI를 호출하기 전에 내부 `/api/search` 로직을 사용해 공식자료 후보를 압축한다.

AI에게 전달되는 공식자료 묶음:

- 법령 후보
- 법령해석례 후보
- 국내재해사례 후보
- 안전보건자료 후보
- 확인시각
- API 실패 및 직접 확인 필요 메모

이제 AI 분석은 질문만 보는 것이 아니라, 현재 확보 가능한 공식자료 후보를 함께 보고 답변한다.

## 다음 단계

1. 법제처 `HTTP 525` 문제를 별도 중계 서버 또는 self-host MCP로 우회 가능한지 검증한다.
2. `verify_citations`와 같은 인용 검증 후처리를 우리 보고서 생성 뒤에 붙인다.
3. D1 또는 KV 캐시를 사용해 반복 법령 검색 비용과 지연 시간을 줄인다.
4. 공식자료 후보가 충분하면 고급 모델 호출 전에 질문 정밀화 단계만 소형 모델로 처리한다.
5. 민감정보 제거기를 추가해 공식자료 검색어에는 사건 핵심 키워드만 남긴다.
